# 96일차 재료 공급·경제 측정 적용

## 경제 설정과 보상

- 시작 Gold: 기존 100 유지.
- 재료 17종 가중치: 모두 100 유지. 미등록·0·음수 가중치는 100으로 보정.
- 1성 구매: 25 + (페이즈-1)×5 + ((깊이-1)/3의 정수값)×3.
- 제거: 35 + (페이즈-1)×5.
- 회복: 20 + (페이즈-1)×4, 기존 HP 1 회복.
- 강화: 45 + (페이즈-1)×8 + ((깊이-1)/5의 정수값)×5.
- 승리 Gold: 일반 15·정예 25·중간 보스 40·최종 보스 60, 페이즈당 +5.
- 승리 Gold는 **개발용 임시값**. 실제 수급과 구매 여유를 기록한 뒤 조정.
- 동일 런의 같은 페이즈·스테이지는 Gold 1회 지급. 지도 노드 정규화·저장 복원·분기 재선택에도 중복 지급 차단.
- 패배·비전투 노드는 승리 Gold 지급 제외.
- 이벤트 구매·회복 비용과 이벤트 Gold 보상은 기존 규칙 유지.

## 기록과 저장 규칙

- 정상 직접 획득은 왕 제외 1성만 허용. 합성 결과·적·보스·미해금 기물 직접 지급 차단.
- 이벤트 카드 확정 경로에도 일반 획득과 런 고정 해금 상태 검사 추가.
- 후보 재표시·이어하기는 같은 경로·페이즈·깊이·노드·Seed에서 중복 기록 제외.
- 전투 보상 후보 Seed에 지도 Seed·완료 페이즈·노드 반영.
- 보스 처치로 다음 페이즈에 진입해도 완료 전 페이즈·깊이·노드에 보상 기록 귀속.
- 실패 구매는 지출 실패로 기록하며 성공 획득에 포함하지 않음.
- 환불은 새 수입에서 제외하고 순지출에서 차감. 저장 Gold 복원은 수입에서 제외.
- 상세 기록은 런당 2,048개 제한. 수입·순지출·실패·획득·합성 누적 총계는 제한 이후에도 계속 증가.
- 최초 2~5성 도달 이력과 승리 지급 이력은 상세 기록 상한과 별도로 저장.
- 내보내기 JSON에는 누적 총계·최초 도달·상세 기록·생략 수 포함. CSV에는 보존된 상세 기록만 포함.
- 누적 총계가 없는 이전 측정 저장은 남아 있는 상세 기록으로 재집계. Unity 직렬화가 만든 빈 객체와 실제 누적 완료 여부 구분.
- 측정 항목이 없는 구버전 저장은 빈 이력과 복원 Gold를 기준으로 진행.

## Unity 확인 절차

1. F:\Project-Eta에서 스크립트 컴파일 완료까지 대기.
2. `Project Eta > Day 96 > Generate Balance Report` 실행. Docs/Validation/Day96BalanceSampling.md 생성 확인.
3. Boot 씬부터 새 런 시작. 정상 전투 승리 후 Gold가 증가하는지 확인.
4. F1 → 상태 페이지 → 아래쪽 `96일차 경제 측정` 확인. 후보·획득·구매·합성 이후 집계 변화 확인.
5. 2성 이상을 실제 합성하여 최초 페이즈·깊이·턴 기록 확인. 메뉴로 돌아갔다가 이어하기 후 기록 유지 확인.
6. `측정 JSON / CSV 저장` 클릭. Console의 저장 경로 확인. 같은 런은 같은 파일명으로 최신 기록 덮어쓰기.
7. 정상 플레이 3런 이상에서 획득 재료, 최초 2~5성 도달 시점, Gold 부족 구매와 회복·강화 사용량 수집.

실제 화면 배치·버튼 조작 감각과 전체 런 플레이는 사용자 확인 단계다. 추가 수동 코드 수정 지시는 없다.

## 후보 샘플링 결과와 조정 판단

보고서: [Day96BalanceSampling.md](Validation/Day96BalanceSampling.md).

- 경로 3개 × 해금 상태 2개 × Seed 1,000개 × 후보 3개 = 후보 자리 18,000개 검증.
- 기본 해금 풀은 11종, 전체 해금 풀은 17종. 미해금 6종은 기본 상태에서 0회 출현.
- 전부 해금 상태에서 17종 모두 Reward·Shop·Event 후보에 출현.
- Knight는 레시피 직접 투입 슬롯 8개로 다른 재료보다 사용 범위가 넓다. 필요량·소모 속도 전체 실측은 별도다.
- 보유·사망 카드가 없는 조건의 후보 분포다. 실제 시작 덱과 진행 중 보유 제한은 실제 런 기록으로 평가.
- 재료 가중치와 가격은 관측 전 기존값 유지. 전투 Gold 지급 누락만 개발용 임시 보상으로 보완.
- 실제 완주 시간·난이도·합성 속도와 확정 수치 조정은 아직 수행하지 않음.

## 검증 결과

- 최종 전체 EditMode: 800개 통과, 실패 0개. 이번 일차 신규 30개 포함.
- 최종 PlayMode: 기존 능력 UI·보드 입력 2개 통과.
- Windows 64비트 개발 빌드: 최종 코드로 성공.
- 독립 검토의 상세 상한 후 총계 누락을 실패 테스트로 재현하고 누적 총계 저장으로 수정.
- 누적 총계 없는 이전 저장의 직렬화 호환 문제를 실패 테스트로 재현하고 완료 플래그로 수정.
- 원본 에디터를 유지하고 별도 검증 복사본에서 테스트와 빌드 수행.
- 이번 요청에서 커밋·푸시하지 않음.
