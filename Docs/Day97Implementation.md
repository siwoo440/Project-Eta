# 97일차 난이도 곡선·전투 측정 적용

초반 편성 종류를 제한하고 페이즈 진행에 따라 일반 5종·정예 3종을 단계적으로 해금했다. 같은 전투 종류의 직전 원형은 다음 생성에서 제외하며, F1에서 다음 편성과 보스 HP 구간을 강제로 확인할 수 있다.

---
## 단계별 적용 결과

| 단계 | 구현 내용 |
|---|---|
| 1. 콘텐츠 잠금 | 일반 원형 2→4→5종, 정예 원형 1→2→3종 순서로 해금 |
| 2. 반복 방지 | 같은 전투 종류의 직전 원형 제외, Seed 혼합으로 선택 분포 보정 |
| 3. 실제 난이도 측정 | 원형·종류별 전투 수, 승패, 턴, 왕 HP 손실, 위협도 누적과 96일차 저장 이관 |
| 4. 디버그 도구 | F1에서 다음 전투 1회 원형 선택과 보스 HP 75%·50%·25% 적용 |
| 5. 자동 검증 | 5,000개 편성 표본과 중간·최종 보스 시작 적·증원 구성 비교 |

## Unity 확인 절차

1. Boot 씬에서 새 런 시작
2. 1페이즈 일반 전투를 두 번 이상 진행해 전열·교란 원형만 나오는지 확인
3. F1 → 전투 도구 → 다음 적 편성에서 자동·이전·다음 선택
4. 다음 일반 또는 정예 전투 진입 후 선택한 원형 로그 확인
5. 보스 전투에서 F1의 50% 버튼을 누르고 다음 상태 검사에서 Phase 2·증원·예고 확인
6. 전투 종료 후 F1 상태의 원형 난이도 승률·평균 턴·왕 HP 손실 확인
7. 측정 JSON·CSV 저장 후 `profileId`, `stageType`, `startingKingHp` 열 확인
8. `Project Eta > Day 97 > Generate Difficulty Report` 실행 후 보고서 생성 확인

## 검증 기준

자동 표본은 해금 원형 도달, 직전 원형 연속 반복 0회, 정예 위협도 우위, 5페이즈 위협도 상승을 확인한다. EditMode 830개와 PlayMode 2개가 통과했고 Windows 64비트 Development 빌드에 성공했다. 독립 검토의 Important 5건을 회귀 테스트와 함께 수정했다. 중간 보스는 시작 적 3기·라운드 증원 2기, 최종 보스는 시작 적 4기·라운드 증원 3기로 구분된다.

실제 체감 난이도와 수치 확정은 전체 런 3회 이상의 플레이 기록 확인이 필요하다.
