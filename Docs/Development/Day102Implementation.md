# 102일차 경로·이벤트 구현

지도에서 전투와 성장 기회를 고르고, 이벤트에서 지불할 비용과 실제로 얻은 결과를 확인하는 흐름을 추가했다.

---
## 적용 순서

1. **경로:** 새 경로 생성에 깊이별 종류·가중치·연속 제한을 연결했다. 2~3분기를 제공하고 첫 전투 이후 각 페이즈의 3·7번 깊이는 전투, 5·10번 깊이는 기존 보스 흐름을 사용한다.
2. **이벤트:** 기획서 EV01~EV35의 A·B·C, 총 105개 선택지를 JSON 데이터로 추가했다. 공통 10종과 각 페이즈 전용 5종을 현재 실행 화면에 연결했다.
3. **선택과 화면:** 비용·효과·선택 불가 이유를 카드에 항상 표시한다. 강화·제거·교환 대상은 페이지당 두 장, 이전·다음·취소 버튼은 별도 행이다. 대상 확정 전에는 비용을 받지 않는다. 확정 후 실제 Gold·왕 HP·카드 변화와 저장 결과를 보여준다.
4. **저장:** 최초 진입의 이벤트 정의·Seed와 완료 결과를 런에 저장한다. 재입력·이어하기로 같은 보상을 다시 받지 못하며, 저장 실패 화면에서 결과를 재적용하지 않고 재시도한다.

## 적용 규칙과 임시 수치

- 신규 런의 모든 합법 경로는 보스를 포함해 전체 **21~24회 전투**다. 2~5페이즈의 시작 노드가 기존 정책에 따라 자동 완료되는 점을 포함한 구조적 계산이다. 실제 플레이 시간과 승률을 측정한 수치는 아니다.
- 각 깊이의 상점·보상·이벤트 조합으로 같은 종류의 연속 선택은 최대 2회다. 상점·이벤트가 있는 경로를 노출하지만 플레이어가 반드시 선택하도록 강제하지 않는다.
- 3분기 확률 65%, 세 번째 후보의 깊이별 가중치, 이벤트 공통 10·전용 14는 **임시값**이다. 이벤트 비용·보상 수치 역시 기획서의 임시 수치를 그대로 데이터화했다.
- 왕 HP 비용으로 사망 불가, 회복은 최대 HP 제한. 카드 보상·교환은 런 시작 시 해금된 1성만 가능하며 정상·사망 합산 동일 PieceId 최대 3개다. 2~5성 직접 지급 없음.
- 제거·교환 대상은 1성, 교환 결과는 다른 PieceId다. 강화는 선택 카드의 HP·ATK를 각각 적용하고 원본 에셋은 수정하지 않는다.
- 합성 연결 보상은 공개 또는 이미 발견한 레시피의 1성 재료 후보만 사용한다. 숨겨진 레시피를 노출하지 않는다.
- 완료한 이벤트 ID는 같은 런에서 제외한다. 후보 소진 시 무보상 통과를 제공한다.
- 선택 단서는 **후보 열람 이력과 안내**다. 정식 단서 원문·핵심 8단서·도감·진엔딩 조건 구현은 이번 범위에 포함되지 않는다. 이미 열람한 정보여도 기본 보상은 유지한다.

## 기존 저장과 호환

정상적인 기존 5페이즈 저장 그래프는 강제 재생성하지 않는다. 새로 만드는 페이즈와 새 런에 신규 규칙을 적용하므로 전체 21~24전투 보장은 새 런 기준이다. 구형 단일 페이즈 저장의 기존 정규화 정책은 유지한다.

구형 이벤트 저장에는 신규 정의 스냅샷이 없으므로 현재 노드에서 신규 풀의 이벤트를 최초 확정한다. 이후 미완료 선택과 완료 결과는 동일하게 복원한다. 구형 7종 이벤트 화면을 그대로 복원한다는 의미는 아니다. 영구 저장의 선택 정보 ID는 선택 필드로 추가하며 기존 버전 3을 유지한다.

## Unity에서 직접 확인할 순서

별도 Inspector 연결과 수동 파일 수정은 없다.

1. F:/Project-Eta를 Unity에서 열고 재생을 중지한 뒤 컴파일 완료를 기다린다.
2. **새 런**을 시작한다. 첫 전투 후 지도에서 2~3분기와 상점·보상·이벤트가 나뉘는지 확인한다.
3. 이벤트에서 비용·효과와 비활성 사유를 읽고, 강화·교환·제거의 대상 화면에서 취소해 자원이 유지되는지 확인한다.
4. 대상이 많은 상태에서 이전·다음으로 마지막 카드까지 이동하고 버튼 겹침을 확인한다.
5. 선택을 확정해 실제 전후 수치와 획득·제거 카드가 맞는지 확인한다. 이어하기 후 같은 결과인지 확인하고 ‘다음 경로’를 누른다.

사람이 실제 전체 런을 완주하며 느끼는 난이도·소요 시간과 실제 보드 카메라에서의 최종 가독성은 별도 수동 검수 대상이다.
