## 실패 재현과 수정

1. **초기 계약:** 리소스·경로 규칙·저장 필드가 없는 상태에서 3개 실패(InitialRed.xml), 구현 후 3개 통과(InitialGreen.xml).
2. **효과 안내:** 마우스를 올리기 전에는 효과 설명이 보이지 않는 실제 UI 실패(DetailsRed.xml)를 확인했다. 선택적 상시 설명 표시를 추가했다.
3. **재사용 위치:** 결과 화면의 ‘다음 경로’ 제목이 이전 상세 카드의 y=57 위치에 남는 실패(ReuseRed.xml)를 확인했다. 카드 재설정에서 제목 위치와 크기를 함께 초기화했다.
4. **대상·탐색 겹침:** 대상 페이지의 실제 버튼 영역이 겹치는 실패(PagingRed.xml)를 확인했다. 대상 두 장과 탐색 버튼을 별도 행으로 배치했다. 첫 페이지부터 마지막까지 모든 대상 도달·버튼 영역 비중첩·취소 자원 보존을 검사했다(PagingGreen.xml 7개 통과).

최종 렌더와 전체 테스트·빌드는 위 수정과 탐색 글자 크기 보정까지 포함한 소스로 다시 실행했다. 마무리 커밋 전에도 같은 소스로 전체 EditMode 995개·PlayMode 26개를 재실행해 실패 0개를 확인했다. 빌드는 최종 구현 완료 시 성공한 동일 소스 결과이며 문서 추가 후 다시 빌드하지 않았다.

## 검증 내용

- 음수 Seed 포함 -64~191의 동일 Seed 재현, 노드 ID 중복·고립·막다른 길·깊이 건너뛰기·불법 킹 이동 없음.
- 깊이 5 중간 보스와 깊이 10의 페이즈별 보스 규칙, 연속 동일 종류 최대 2회, 경로별 상점 최대 4회·이벤트 최대 3회.
- 실제 첫 승리 처리에서 신규 그래프 사용, 정상 저장 그래프의 불필요한 재생성 없음.
- 105선택지의 Gold·왕 HP·HP/ATK 개별 강화·획득·제거·교환·열람 이력 반영과 두 번째 적용 거부.
- Gold 부족·왕 HP 1·최대 HP 회복·대상 없음·카드 상한·미해금 카드·자기 자신 교환 차단. 모든 이벤트에서 자원이 부족해도 통과 선택 존재.
- 합성 연결 보상은 공개/발견 레시피 재료로 한정. 일반·사망 카드 합산 3개 제한.
- 같은 런의 완료 이벤트 ID 제외와 후보 소진 시 무보상 통과.
- 미완료 이벤트 정의·완료 결과의 JSON 복원과 안전 이어하기 검증, 재로드·재입력 시 중복 보상 차단.
- 저장 실패 후 같은 결과의 저장 재시도, 오래된 콜백 무시, ‘다음 경로’ 중복 진행 차단.
- 선택 정보 후보를 이미 읽었어도 기본 보상 유지, 별도 영구 ID 목록의 JSON 복원.

## 화면 확인과 한계

실제 StageBoardOverlayUI·RunEventPresenter·카드 데이터로 선택·대상·중간 페이지·마지막 페이지·결과 화면을 렌더했다. UiPreviewReleased/EventMain.png·EventTargets.png·EventTargetsMiddle.png·EventTargetsLast.png·EventResult.png를 생성했다. 특히 중간 페이지의 이전·다음·취소 글자와 결과 화면의 진행 제목 정렬을 직접 확인했다.

이는 독립 검증 씬의 Canvas를 정면 카메라로 렌더한 배치 검사다. 실제 전체 전투 씬을 촬영한 결과나 사람이 전체 런을 완주한 결과는 아니다. 실제 보드 카메라에서의 최종 가독성, 전투 소요 시간·난이도·승률, 35종의 서사 완성도는 별도 플레이 검수가 필요하다.

35종의 선택 단서는 후보 열람 ID와 안내만 기록한다. 정식 단서 원문·핵심 단서·도감·진엔딩 조건은 이번 완료 범위가 아니다. 추첨 가중치와 기획서의 수치는 임시값이다. 전체 전투 수 보장은 신규 런 기준이며 기존 저장 그래프는 유지한다.
