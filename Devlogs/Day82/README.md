# 82일차: 왼쪽 F1 디버그 패널과 전투 도구 통합

---

## 개발 목표

전투 화면에 항상 표시되던 승리·패배·배속 개발 버튼을 제거하고 F1 디버그 패널 안으로 통합했다.

패널이 실제 플레이 화면을 과도하게 가리지 않도록 왼쪽 위의 좁은 영역만 사용하고, 상태·전투·AI 기능을 탭으로 분리했다.

---

## 왼쪽 고정 반응형 배치

패널은 화면 왼쪽 위 12px 여백에 고정된다.

- 최소 폭: 320px
- 최대 폭: 420px
- 기준 폭: 화면 너비의 22%
- 최대 높이: 700px
- 작은 해상도: 화면 경계 안으로 자동 축소

프로젝트 기본 해상도인 1024×768에서는 패널 폭이 340px 이하가 되도록 회귀 테스트를 추가했다.

---

## 패널 UI 구성

F1 패널을 다음 세 페이지로 구분했다.

| 페이지 | 기능 |
| --- | --- |
| 상태 | 씬·빌드·런 흐름·스테이지·Seed·턴·결과·킹 HP·기물·카드·재화 표시 |
| 전투 도구 | 강제 승리·강제 패배·1배속·2배속·3배속 선택 |
| AI 분석 | 기존 AI 후보 점수·Preview·실제 적 턴 성능·Console 출력 |

상단에는 현재 Scene·Flow·Turn을 항상 표시하고, 하단에는 빌드 종류·FPS·프레임 시간을 표시한다.

선택 탭은 파란색, 강제 승리는 녹색, 강제 패배는 붉은색, 선택 배속은 노란색으로 구분했다.

---

## 전투 결과 통합

강제 승리와 강제 패배는 별도 결과 상태를 만들지 않고 기존 `BattleController.EndBattle()` 진입점을 사용한다.

따라서 보상, 지도 전환, 런 실패, 전투 결과 연출, Steam Achievement 연결을 포함한 기존 후속 흐름이 동일하게 실행된다.

버튼은 다음 조건에서만 활성화된다.

- 현재 런 흐름이 Battle
- TurnManager 연결 완료
- 전투 결과가 아직 BattleEnded가 아님

## 클릭 관통 차단

IMGUI 기반 F1 패널을 클릭했을 때 아래 체스판이 함께 반응하지 않도록 다음 입력 경로에 공통 차단을 적용했다.

- 일반 보드 선택·이동·공격
- Route Map 노드 선택
- 2×2 대형 보스 전용 클릭 공격

Input System의 왼쪽 아래 기준 좌표를 IMGUI의 왼쪽 위 기준 좌표로 변환해 패널 포함 여부를 판정한다.

- 1개 노드 층: 중앙 `X=0`
- 2개 노드 층: `X=-1.3, 1.3`
- 3개 노드 층: `X=-2.4, 0, 2.4`
- 시작 노드: `X=0, Z=-4`
- 최종 보스: `X=0, Z=4`
- 같은 층 노드: 작은 Z 편차로 수평 일렬 배치 완화
- 모든 노드: 두 표시 반지름과 `0.12` 여백을 합산한 최소 거리 검사

시작·중간 보스·최종 보스 같은 단일 노드를 먼저 고정하고, 분기 노드는 원래 슬롯에서 가장 가까운 충돌 없는 위치를 탐색한다.

현재 노드, 선택 노드, 미래 노드, 아이콘, 연결선, 지도 King은 `RouteMapBoardController.NodePositions` 좌표표를 함께 사용한다.
