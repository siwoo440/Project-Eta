# 85일차 : 81종 기물 로스터 기준 및 검증 체계 구축

---
## 개발 목표

84일차에서 확인한 1~5성 합성 성장 진단을 기반으로, 이후 기물·합성 데이터를 확장하기 전에 V1.0 목표 플레이어 기물 81종의 식별 기준을 코드에 고정했다.

현재 PieceDatabase에 등록된 26종을 유지하면서 목표 로스터 81종과 비교해 미등록 기물, 중복 PieceId, 예상 밖 ID, 등급·분류·역할 태그 불일치를 자동으로 확인할 수 있는 검증 체계를 구축했다.

---
## 작업 내용

- `PieceRosterEntry`와 `PieceRosterCatalog` 추가
- V1.0 목표 플레이어 기물 81종의 PieceId·표시명·등급·분류·역할 태그 기준 추가
- 목표 등급 분포 1성 18종·2성 19종·3성 18종·4성 18종·5성 8종 고정
- 현재 등록 26종의 기존 PieceId·등급·분류·역할 태그 기준 유지
- 미등록 1~2성 11종과 3~5성 44종을 포함한 목표 ID 목록 추가
- `PieceRosterValidator`와 `PieceRosterValidationReport` 추가
- 현재 PieceDatabase와 목표 81종 사이의 누락·중복·예상 밖 ID 검증 추가
- 등급·PieceCategory·PieceRoleTag 메타데이터 불일치 검증 추가
- 등급별 현재 등록 수와 목표 수를 비교하는 요약 기능 추가
- Unity Editor 메뉴에서 현재 로스터를 확인하는 Day85 검증 메뉴 추가
- 81종 목표 수·PieceId 고유성·현재 26종·미등록 55종을 확인하는 EditMode 테스트 추가

## 목표 로스터 기준

| 등급 | 목표 수 | 현재 등록 | 현재 미등록 |
| --- | ---: | ---: | ---: |
| 1성 | 18 | 12 | 6 |
| 2성 | 19 | 14 | 5 |
| 3성 | 18 | 0 | 18 |
| 4성 | 18 | 0 | 18 |
| 5성 | 8 | 0 | 8 |
| 합계 | 81 | 26 | 55 |

85일차에서는 미등록 55종의 실제 PieceDefinition 에셋과 전투 기능을 한 번에 생성하지 않는다.

이번 일차의 목적은 이후 데이터 등록 과정에서 ID 충돌과 잘못된 등급·분류·역할 정보가 섞이지 않도록 목표 로스터의 기준을 먼저 고정하는 것이다.

---
## 로스터 검증

Unity Editor 상단 메뉴의 다음 항목으로 실제 PieceDatabase를 검사할 수 있다.

```text
Project Eta > Day 85 > Validate 81-Piece Roster
```

검증 결과에는 다음 정보가 출력된다.

| 항목 | 내용 |
| --- | --- |
| 등록 | 목표 81종 중 현재 등록된 기물 수 |
| 미등록 | 목표 로스터에 있으나 PieceDatabase에 없는 기물 수 |
| 예상 밖 ID | 목표 로스터에 존재하지 않는 PieceId 수 |
| 중복 ID | 동일 PieceId가 두 번 이상 등록된 수 |
| 메타 불일치 | Grade·Category·RoleTags가 목표 기준과 다른 수 |
| 잘못된 정의 | null 또는 빈 PieceId 데이터 수 |

현재 프로젝트 데이터 기준 기대 상태는 다음과 같다.

```text
등록 26/81
1★ 12/18
2★ 14/19
3★ 0/18
4★ 0/18
5★ 0/8
미등록 55
```

미등록 55종은 오류가 아니라 현재 개발 단계에서 의도된 상태다.

예상 밖 ID, 중복 ID, 메타데이터 불일치와 잘못된 정의는 이후 데이터 확장 과정에서 발생하면 확인이 필요한 구조 문제로 취급한다.

---
## 81종 카탈로그 운영 기준

PieceId는 저장·합성·해금·보상·상점·이벤트·업적과 같은 여러 시스템이 참조하는 식별자이므로 표시 이름과 분리해 관리한다.

기존 26종의 PieceId는 현재 프로젝트 값을 유지하며 신규 기물은 카탈로그에 정의된 ID를 기준으로 이후 PieceDefinition을 생성한다.

플레이어 목표 로스터는 Monster와 Boss 분류를 제외하고 관리한다. 보스와 몬스터는 별도 적 콘텐츠 데이터로 유지한다.

PieceRoleTag는 한 기물이 여러 역할을 동시에 가질 수 있는 Flags 구조를 유지하며 이후 AI 평가, 적 편성, 카드 검색과 UI 아이콘 분류에 재사용할 수 있게 한다.
