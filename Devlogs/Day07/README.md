# 7일차 개발 일지 — 고위험 기능·카메라 검증

**날짜**: 2026-09-03
**목표**: 나중에 갈아엎기 어려운 핵심 로직(페어리 이동 패턴, 슬라이더 탐색, 2×2 대형 기물 점유)을 먼저 검증하고, 45~60도 범위의 테이블 카메라 각도를 확인한다.

## 사용자 확인 사항(사전 질의)

- 폰 이동: "매 턴 전방 최대 2칸까지 이동 가능(첫 이동 제한 없음)"으로 확정.
- 폰 공격: "전방 1칸 + 대각선 앞 좌우 1칸" 모두 공격 가능(대각선은 공격 전용, 이동 불가)으로 확정.
- 확정한 두 규칙은 [CoreRules_Checklist.md](../../Docs/CoreRules_Checklist.md)의 [확정] 섹션에 반영.

## 오늘 한 일

### 1. 이동/공격 계산 시스템 (`Scripts/Board/MovementResolver.cs`, `MovementResult.cs`)
- `MovementResolver.GetReachableTiles(movementType, origin, isPlayerPiece, board)` — 기물 종류별로 이동 가능 칸(`MoveTiles`)과 공격 가능 칸(`AttackTiles`)을 분리해 계산.
- 슬라이더(룩/비숍/퀸): 방향별로 막힐 때까지 이동, 적을 만나면 그 칸을 공격 칸으로 추가하고 정지, 아군을 만나면 그냥 정지.
- 점프(나이트): 중간 칸 점유 여부와 무관하게 8개 도약 좌표로 이동/공격 판정.
- 페어리 합성(아크비숍=비숍+나이트, 챈슬러=룩+나이트, 아마존=퀸+나이트): 두 이동 패턴 결과를 `MergeFrom`으로 합침.
- 킹: 8방향 슬라이더를 1칸으로 제한.
- 폰: 확정된 규칙대로 전방 최대 2칸 이동(1칸 막히면 2칸 불가) + 전방·대각선 좌우 공격.

### 2. 2×2 대형 점유 미니 테스트 (`BoardState.TryOccupyArea`/`ClearArea`)
- 사각 영역 전체가 비어있는지 먼저 검사한 뒤, 통과하면 영역 내 모든 칸의 `OccupyingPiece`를 같은 기물 참조로 채우는 방식으로 2×2 이상 기물 점유를 검증.
- 정식 다중 칸 이동/충돌 처리는 이후 단계에서, 이번엔 "점유가 되는가"만 확인.

### 3. 테이블 카메라 45~60도 검증 (`Scripts/Board/TableCameraRig.cs`, `Battle.unity`)
- Main Camera에 부착. `W` 키를 누르면 60도로, `S` 키를 누르면 45도로 `SmoothDamp` 기반 빠른 전환(약 0.25초)이 일어나며, `OnGUI`로 현재 각도 표시.
- 기존 3일차의 고정 45도 값을 대체하고, 시작 각도는 최소값(45도)에서 출발.

### 4. 자동 단위 테스트 (`Assets/ProjectEta/Tests/EditMode/`)
- `MovementResolverTests`: 룩 슬라이드가 끝까지 가는지/적에서 멈추는지/아군에서 멈추는지, 나이트가 장애물을 무시하는지, 폰의 2칸 이동·차단·대각선 공격, 아크비숍의 합성 이동 검증.
- `BoardOccupancyTests`: 2×2 영역 점유 성공/실패, 해제(`ClearArea`) 동작 검증.

### 5. 사용자 확인 사항
- Test Runner에서 `MovementResolverTests`/`BoardOccupancyTests` 포함 전체 테스트 통과 확인.
- Battle 씬 Play 후 W/S 키로 카메라 각도를 45도·60도 사이에서 빠르게 전환해보며 10×10 보드 가독성을 확인.

## 오늘 하지 않은 것

- 이동 결과를 실제 클릭 입력·이동 실행과 연결하는 것(2단계, 16~30일차 예정).
- 2×2 기물의 실제 시각화·이동·충돌 처리(현재는 점유 자료구조 검증만).
- 앙파상·프로모션 등 폰의 나머지 특수 규칙(61~75일차 예정).
