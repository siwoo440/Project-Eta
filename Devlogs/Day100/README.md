## 개발 결과

기존 좌석 카메라에 WASD로 의자에서 일어나 방 안을 이동하고, 플레이어 의자에 접근해 F키로 다시 앉는 기능을 연결했다. 기존 방·의자 모델은 유지하고 이동용 충돌체를 별도로 생성했다.

이번 작업은 추가 100일차다. 기존 보스 상세 데이터·선택·저장 복원 기반 계획은 101일차로 이동한다. 별도 탐색 구역·문·단서·스토리 진행은 후속 개발 대상이다.

## 조작과 이동 기준

| 입력·항목 | 적용 내용 |
|---|---|
| WASD | 의자에서 일어나 바라보는 방향 기준 이동 |
| 마우스 이동 | 이동 중 주변 둘러보기 |
| 의자 가까이에서 F | 이전 좌석/보드 시점으로 복귀 |
| F2 / F3 / F4 | 맨 위 / 기본 / 앉은 주변 시점 |
| F4에서 우클릭 드래그 | 기존 앉은 상태 둘러보기 |
| 숫자 1~0·F1 | 기존 손패 선택·디버그 패널 유지 |
| 이동 속도 | 초당 4 월드 단위 |
| 의자 접근 거리 | 수평 3.4 단위 이내·같은 바닥 높이 |
| 선 눈높이 | 발 위치에서 5.25 단위 |

이동 거리·속도·눈높이는 현재 큰 방 모델에 맞춘 임시 기준이다. 일시정지 기본 키는 Esc이며 변경된 키는 안내에 반영한다.

## 최종 검증

| 검사 | 결과 |
|---|---|
| 전체 EditMode 재검사 | 870개 통과·실패 0개 |
| 전체 PlayMode 재검사 | 12개 통과·실패 0개 |
| Windows 64비트 개발 빌드 | 성공·실행 파일 확인 |
| 코드 일치 | 추적 소스 483개·100일차 적용 파일 18개 검증 복사본과 일치 |
| 신규 C# 주석 | 빈 줄을 제외한 각 줄 한글 주석 확인 |
| Git 변경 공백 검사 | 통과 |

Unity 6000.3.21f1 검증 복사본에서 검사했다. 입력 상태 주입과 실제 런타임 컴포넌트로 이동·충돌·복귀·필수 화면 전환을 검사했으며, 전체 게임을 사람이 플레이한 시각·체감 검수를 대신하지 않는다.

상점 카메라 충돌과 이동 중 보상 화면의 입력 차단 문제는 실패를 재현한 뒤 수정했다. 기존 증원 검사는 증원 시점·횟수·중복 차단 검증을 유지하면서 무작위 초기 편성과 겹치지 않는 시험 위치로 분리했다. 제품의 점유 칸 증원 처리 규칙은 변경하지 않았다.

## 101일차 개발 방향

쉽게 말하면 페이즈마다 다른 보스를 정해 두고, 같은 런에서는 저장 후 다시 시작해도 같은 보스와 규칙을 만나는 기반을 만드는 작업이다.

현재는 중간·최종 보스 전용 라운드와 공통 보스 행동·예고·체력 구간 처리 기반이 있다. 다음에는 보스 15종의 상세 데이터와 페이즈별 후보 풀, 기본/강화형, Seed 선택, 선택 결과 저장·복원 구조를 연결한다.

101일차 완료 기준은 후보 밖 보스 선택·중복 추첨·이어하기 시 보스 변경을 막고 기존 보스 전투가 유지되는 상태다. 모든 보스의 모델·전용 패턴·최종 밸런스 완성은 이후 일차에서 진행한다.
